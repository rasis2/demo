Module 01

What is Software Engineering?

The application of engineering principles and practices to the design, development, testing, and maintenance of software.

🎯

Discipline

A structured, systematic approach to building software — not just "typing code".

🧠

Engineering Mindset

Plan, measure, and design before building. Handle complexity and change in a controlled way.

🛠️

Whole Product

Covers not only code, but also requirements, testing, deployment, documentation, and maintenance.

"Software engineering is programming integrated over time. Treating programming as only coding is the first big mistake."
Module 01

Program vs Software

A program is a set of instructions; software is the complete product around it.

ProgramSoftware
Code / instructions onlyProgram + data + documentation
Often written quicklyBuilt with planning and process
Solves one narrow taskPart of a larger system or product
Rarely updatedContinuously maintained & evolved
Single developerTeam of engineers
Module 02

Software Development Life Cycle

SDLC is the step-by-step process used to design, develop, and maintain software. Each phase produces a deliverable.

01

Planning

Goals, scope, cost & schedule estimation.

02

Analysis

Gather & document requirements.

03

Design

Architecture, data & UI design.

04

Implementation

Write code, build the product.

05

Testing

Find & fix defects, verify quality.

06

Deployment

Release to users / production.

07

Maintenance

Fix bugs, add features, evolve.

Module 02

SDLC Models

Different ways to organise the SDLC phases — each suited to different project types.

💧

Waterfall

  • Linear, sequential phases
  • Each phase finishes before the next
  • Clear requirements required early
  • Rigid — hard to change course
🔁

Agile (e.g. Scrum)

  • Iterative, small increments
  • Continuous feedback & change
  • Frequent releases to users
  • Self-organising, collaborative teams
🐌

Iterative & Incremental

  • Build in repeated cycles
  • Grow the product feature by feature
  • Earlier feedback on working parts
🔄

Spiral

  • Risk-driven iterations
  • Each loop refines & manages risk
  • Good for large, complex projects
Module 03

Requirement Engineering

Understanding what the client and users actually need before any code is written.

📋

Functional Requirements

What the system must do — specific features & behaviours.

  • "User can upload a PDF"
  • "System sends an email receipt"
  • "Login requires username & password"
⚖️

Non-Functional Requirements

How the system should behave — quality attributes.

  • Performance: loads under 2s
  • Security: data is encrypted
  • Usability, reliability, scalability
The hardest part of building software is not coding, but deciding precisely what to build.
Module 03

Software Design

Blueprint for the solution before coding — architecture, modules, and how pieces fit together.

🏗️

Architecture

High-level structure: system components, layers, and their relationships (e.g. client–server).

🧩

Modularity

Breaking the system into smaller, independent, reusable modules that are easy to manage.

🗄️

Data Design

How data is stored, organised, and accessed — database schemas and data structures.

🎨

UI / UX

Designing the user interface and experience so the product is intuitive to use.

📏

Design Principles

SOLID, DRY, KISS, YAGNI — guidelines that keep code clean and maintainable.

🔐

Security & APIs

Designing secure interfaces and contracts between components and external services.

Module 04

Implementation (Coding)

Translating the design into working code — the phase people usually picture first.

💻

Good Practices

  • Write clean, readable code
  • Meaningful names & comments
  • Follow language conventions
🔄

Version Control

  • Git tracks all changes
  • Branches for features/fixes
  • Revert & collaborate safely
👥

Teamwork

  • Code reviews for quality
  • Standards shared across team
  • Continuous integration & delivery
Module 04

Software Testing

Verifying the software meets requirements and is free of defects — quality must be built in, not added at the end.

🧪

Unit Testing

Testing individual functions or components in isolation.

🔗

Integration Testing

Testing that modules work correctly together.

🎬

System / E2E Testing

Testing the complete application as a user would.

✅

Acceptance Testing

Client verifies the software meets agreed requirements.

🤖

Automated Testing

Scripts that run tests every build — fast, repeatable.

🚀

Performance Testing

Check speed, responsiveness, and stability under load.

Module 05

Deployment & Maintenance

Releasing the software to users — and keeping it alive and healthy long after launch.

🚢

Deployment

  • Release to production environment
  • Automated pipelines (CI/CD)
  • Rollback plans if issues occur
🔧

Maintenance

  • Corrective — fix bugs found by users
  • Adaptive — adjust to new environments
  • Perfective — add features & improve
Module 06

Who Builds Software?

Software engineering is a team effort — many roles collaborate across the SDLC.

👔

Product Owner

Owns the vision & priorities, represents the client.

🧑‍💼

Project Manager

Plans schedule, budget, resources, and communication.

🧑‍🎨

UI/UX Designer

Designs the look and user experience.

👨‍💻

Software Developer

Writes and maintains the code.

🧪

QA / Tester

Ensures quality, finds & reports defects.

🏗️

Architect

Designs the overall system structure.

🚀

DevOps Engineer

Builds pipelines, manages deployment & infra.

☎️

Support

Helps users & feeds feedback back to the team.

Module 06

Key Principles & Mindsets

Simple guiding rules that make software easier to build, read, and maintain.

🔁

DRY

Don't Repeat Yourself — avoid duplicating logic; reuse instead.

🙂

KISS

Keep It Simple, Stupid — the simplest solution is usually the best.

🚫

YAGNI

You Aren't Gonna Need It — don't build features you don't need yet.

🧱

SOLID

Five OOP principles for robust, maintainable object-oriented design.

🕰️

First, Make it Work

Working software > perfect software. Improve after it runs.

👂

Embrace Change

Requirements evolve — design so change is cheap.

Wrap Up

Key Takeaways

📐

Process Matters

Follow the SDLC — planning, analysis, design, coding, testing, deployment, maintenance.

💡

Quality is a Habit

Testing, clean code, and good design are continuous — not a final step.

🔄

Adapt the Model

Pick the right SDLC model for the project — Waterfall for stable needs, Agile for change.

🤝

It's a Team Sport

Great software is built by people working together, communicating constantly.

Any fool can write code that a computer can understand. Good programmers write code that humans can understand.
