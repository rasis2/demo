Module 04 · 4.1

Benefits of Preventive Maintenance

A small investment that pays off big in the future.

⏱️

Longer Lifespan

Avoid unnecessary component wear — hardware lasts longer.

🛡️

Data Protection

Regular backups and inspections reduce the risk of data loss.

🔻

Fewer Failures

Reduces equipment failure, downtime, and repair costs.

Without a PM plan: downtime increases and repair costs rise.
Module 04 · 4.1

Building a Maintenance Plan

A plan is built on at least two factors: location/environment and how the system is used.

📍

Environment

  • Dust, temperature, humidity
  • Power quality (surges, spikes)
  • Physical hazards (e.g., construction sites)
💼

Usage

  • Heavy vs. light workloads
  • Portable vs. stationary
  • Critical vs. routine roles
Module 04 · 4.1

Hardware Maintenance Tasks

Routine physical care keeps components cool, clean, and securely connected.

💨

Remove Dust

  • Fan intake & power supply
  • Components inside the case
  • Use compressed air
🔌

Connections

  • Check & secure loose cables
  • SATA storage cables
  • Front panel LED cables
🖱️

Peripherals

  • Clean mouse & keyboard
  • Inspect monitor & cables
  • Check cooling fans
Module 04 · 4.1

Software Maintenance Tasks

Equally important — OS and app updates keep software problems away.

🛡️

Security

  • Security updates
  • Up-to-date virus definitions
  • Scan for spyware & malware
💿

System Health

  • Disk cleanup & defrag
  • Scan disks for errors
  • Verify backups work
🔄

Updates

  • Windows OS patches
  • Driver & firmware
  • Latest application versions
Module 04 · 4.1

Cleaning Safety Tips

Cleaning incorrectly can cause more damage than the dust itself.

🌀

Hold Fan Blades

Hold the fan blades while using compressed air — prevent the rotor from overspinning.

👀

Visual Check

Best way to inspect the CPU fan: check it visually while power is ON — don't spin it by hand.

🚫

No Liquid Inside

Never use a damp cloth or liquid directly on internal components.

The 6-Step Process

A logical, repeatable approach to diagnosing and resolving PC problems.

02

Theory of likely cause.

Test the theory to confirm.

Record findings & outcomes.

Module 04 · Step 1

Identify the Problem

Understand the problem — and protect customer data before touching anything.

🗣️

Gather Information

  • Ask open-ended & closed-ended questions
  • Reproduce the problem if possible
  • Check recent changes
📝

Document & Back Up

  • Record in the work order
  • Back up customer data FIRST
  • Technicians can be held liable
Always back up data first before troubleshooting — technicians are responsible if data is lost.
Module 04 · Step 1

Liability Release Form

If a backup cannot be made, ask the customer to sign a liability release form with these three items:

✅

Permission

Permission to work without a current backup.

🖊️

Release

Release from liability if data is lost/damaged.

📋

Description

Description of the work to be performed.

Module 04 · Steps 2–3

Establish & Test a Theory

Form a likely cause, then test it. If wrong, form a new theory.

🧠

Establish Theory

  • Start with the most obvious / non-invasive cause
  • Use a "divide and conquer" approach
  • Think of common problems first
🔬

Test the Theory

  • Confirm the cause through testing
  • If confirmed → plan a solution
  • If not → new theory or escalate
Module 04 · Steps 4–5

Plan, Implement & Verify

Research the solution, implement it, then verify everything works again.

🔎

Plan & Implement

  • Research solutions (web, manuals)
  • Escalate if beyond your knowledge
  • Implement the chosen solution
✔️

Verify Functionality

  • Verify the system works fully
  • Implement preventive measures
  • Show the customer the solution
Module 04 · Step 6

Document Everything

Technical work isn't finished until documentation is complete.

📄

Failed Attempts

Record what didn't work — future technicians know what to avoid.

✅

The Solution

Record the solution that finally worked.

🔁

Avoid Repeat Calls

Good documentation prevents repeat repairs.

Before escalating a ticket: document every test already performed.
