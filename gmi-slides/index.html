Module 04 · Overview

Two Sides of Computer Care

Preventive maintenance is proactive — done regularly to avoid problems. Troubleshooting is reactive — fixing problems after they happen.

Preventive MaintenanceTroubleshooting
Proactive — prevents problemsReactive — solves existing problems
Regular checks & adjustmentsDiagnose & fix issues
Extends component lifeRestores normal operation
Reduces downtime & repair costsUses a structured 6-step process
4.1 · Preventive Maintenance

Benefits of Preventive Maintenance

A preventive maintenance plan keeps the IT infrastructure reliable, efficient, and cheaper to run.

⏱️

Extends Component Life

Prevents undue wear on parts, so hardware lasts longer.

🛡️

Protects Data

Regular backups and checks reduce the risk of data loss.

🔻

Fewer Failures

Reduces equipment failures, downtime, and repair costs.

"Preventive maintenance helps protect computer equipment against future problems."
4.1 · Preventive Maintenance

Building a Maintenance Plan

A plan is developed based on at least two factors: the computer's location/environment and how it is used.

📍

Environment

  • Dust, temperature, humidity
  • Power quality (surges, spikes)
  • Physical hazards
💼

Usage

  • Heavy vs light workload
  • Mobile vs fixed location
  • Critical vs non-critical role
Without a plan: increased downtime and increased repair costs.
4.1 · Preventive Maintenance

Hardware Maintenance Tasks

Routine physical care keeps components cool, clean, and securely connected.

💨

Dust Removal

  • Remove dust from fan intakes
  • Clean power supply vents
  • Clear dust from components
🔌

Connections

  • Check & secure loose cables
  • Verify storage device cables
  • Ensure firm connections
🖱️

Peripherals

  • Clean mouse & keyboard
  • Inspect monitor & cables
  • Check cooling fans spin
Cleaning tool of choice inside a case: compressed air.
4.1 · Preventive Maintenance

Software Maintenance Tasks

Keeping the operating system and applications updated is just as important as physical cleaning.

🛡️

Security

  • Review security updates
  • Update virus definitions
  • Scan for spyware & malware
💿

System Health

  • Disk cleanup & defrag
  • Scan disk for errors
  • Verify backups
🔄

Updates

  • Install OS patches
  • Update drivers & firmware
  • Update applications
4.1 · Preventive Maintenance

Cleaning Safety Tips

Cleaning incorrectly can cause more damage than dust ever will.

🌀

Hold Fan Blades

Hold the fan blades in place when using compressed air to prevent over-spinning the rotor.

👀

Check Fan Visually

Best way to check a CPU fan: visually inspect it with the power ON — don't spin it by hand.

🚫

No Liquids Inside

Never use a damp cloth or liquid cleaner directly on internal components.

4.2 · Troubleshooting Process

The 6-Step Process

A logical, repeatable approach to diagnosing and solving PC problems.

01

Identify

Gather info from the customer.

02

Theory

Establish probable cause.

03

Test

Test theory to find cause.

04

Plan

Plan of action & implement.

05

Verify

Full system functionality.

06

Document

Record findings & outcome.

4.2 · Step 1

Identify the Problem

Before touching anything, understand what's wrong — and protect the customer's data.

🗣️

Gather Information

  • Ask open & closed-ended questions
  • Reproduce the problem if possible
  • Check recent changes
📝

Document & Backup

  • Record details in a work order
  • Back up customer data FIRST
  • Liability if data is lost
Always back up data before beginning any troubleshooting — a technician can be held liable for data loss.
4.2 · Step 1

Liability Release Form

If a backup can't be created, have the customer sign a liability release form containing these three pieces of information:

✅

Permission

Permission to work on the computer without a current backup.

🖊️

Release

Release from liability if data is lost or corrupted.

📋

Description

Description of the work to be performed.

4.2 · Steps 2–3

Establish & Test a Theory

Form a probable cause, then test it. If it's wrong, form a new theory.

🧠

Establish Theory

  • Start with obvious / least invasive causes
  • Use "divide and conquer" approach
  • Consider common problems first
🔬

Test the Theory

  • Confirm the cause by testing
  • If confirmed → plan solution
  • If not → new theory or escalate
4.2 · Steps 4–5

Plan, Implement & Verify

Research solutions, apply them, then confirm everything works again.

🔎

Plan & Implement

  • Research solutions (web, manuals)
  • Escalate if beyond knowledge level
  • Apply the chosen solution
✔️

Verify Functionality

  • Confirm full system works
  • Implement preventive measures
  • Show the customer the fix
4.2 · Step 6

Document Everything

No technical job is finished until the documentation is complete.

📄

Failed Attempts

Record what didn't work, so future technicians know what to avoid.

✅

The Solution

Record the solution that finally resolved the problem.

🔁

Avoid Repetition

Good documentation prevents repeating past repairs.

Before escalating a ticket: document each test that was performed.

Wrap Up

Key Takeaways

🛡️

Maintain Proactively

Regular cleaning and updates extend component life and prevent costly failures.

🔧

Follow the Process

Use the 6-step troubleshooting method every time — don't skip steps.

💾

Back Up First

Always back up data (or get a liability release) before touching a customer's PC.

📝

Document Everything

Record failed attempts and the final solution — the job isn't done until it's documented.

Prevent problems before they happen; solve the rest with a clear, repeatable process.
